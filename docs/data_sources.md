# Data Sources

## How Training Data Is Generated

Training data is **not downloaded** — it is generated on the fly from scenario definitions. The pipeline:

```
Data sources (real incidents)
  │
  ├── 5 hand-authored YAML scenarios (in repo, always available)
  ├── 241 Aiops-Dataset faults (data/groundtruth-all.csv, in repo, 16 KB)
  └── 261 crawled incidents (data/incidents.db, generated by python -m app.main crawl)
        │
        ▼
ScenarioGenerator.batch_generate()
  → converts each incident to a ScenarioDefinition
  → picks topology template (5 options by failure category)
  → builds event timeline (8 templates by failure type)
  → sets correct root causes from taxonomy labels
        │
        ▼
SREEnvironment (per episode)
  → perturbs scenario (±15% timing, ±20% magnitudes) per seed
  → TelemetryGenerator produces metrics, logs, traces
  → agent investigates → reward computed
```

Each seed produces different telemetry for the same scenario. 246 scenarios × unlimited seeds = unlimited training episodes.

## Included in the repo (no downloads needed)

### Builtin Scenarios (5 YAML files)

Hand-authored, covering 5 failure classes: connection pool exhaustion, memory leak, cascading failure, DNS failure, disk full. Located in `scenarios/`.

### Aiops-Dataset Groundtruth (data/groundtruth-all.csv, 16 KB)

241 labeled fault scenarios from a real 46-instance microservice e-commerce system [1]. Fault types: Node CPU Failure, Kubernetes Container Memory Load, Network Latency, Disk Space Consumption, Process Termination, I/O Load, and more. Already in the repo.

```bash
python python -m app.main train --episodes 1000
```

This produces **246 total scenarios** (241 generated + 5 builtins) covering 14 taxonomy leaves.

## Generated locally (30 seconds, needs internet)

### Incident Crawler (data/incidents.db)

Fetches 261 real incidents from public APIs: GCP status page (5), Cloudflare Statuspage API (50), GitHub post-mortems (206). Stored as 288 KB SQLite. Not committed to git — regenerate with:

```bash
python python -m app.main crawl --db-path data/incidents.db
python python -m app.main train --episodes 1000 --incident-db data/incidents.db
```

Of the 261 crawled incidents, 61 have taxonomy labels and become playable scenarios.

## Available but large (for future use)

These are valuable for improving fidelity and validating synthetic-to-real transfer, but are multi-GB and not needed for initial training.

| Source | Size | What it provides | When to use |
|--------|------|-----------------|-------------|
| **Aiops-Dataset full** (logs/metrics/traces) [1] | ~2.8 GB | Real telemetry from 46-instance microservice system across 5 days | Calibrating synthetic telemetry against real data |
| **LogHub** [2] | 30+ GB | 300M+ real production log lines (HDFS, BGL, Thunderbird, OpenStack) with anomaly labels | Improving log template realism |
| **VOID** [3] | ~10K incidents (no bulk download) | Incident metadata from ~590 organisations | When VOID publishes a public API |
| **Microsoft AIOpsLab** [4] | Requires K8s cluster | Real microservice deployment (DeathStarBench) with fault injection | Layer 2 validation after synthetic training works |
| **LitmusChaos ChaosHub** [5] | N/A (experiment catalog) | 50+ Kubernetes fault experiment definitions | Expanding taxonomy coverage |
